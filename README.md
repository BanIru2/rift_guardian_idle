# 균열 수호자 · Rift Guardian Idle

Unity 기반의 모바일 2D 방치형 액션 RPG입니다. 자동 전투로 얻은 재화로 캐릭터를 강화하고, 스킬을 선택해 보스에 도전합니다.

**현재 상태: Unity 기본 프로젝트 생성 완료, 게임 기능 구현 전.** 저장소 초기화와 Unity용 `.gitignore` 파일 추가를 마쳤으며, `rift_guardian_idle/` 아래에 Unity 프로젝트와 기본 씬이 있습니다. 아래 게임 기능은 구현 계획이며, 플레이 가능한 빌드와 성능 측정 결과는 아직 없습니다.

## 개발 배경

이전 개인 프로젝트 `neglectful_beauty`에서는 AI를 적극 활용해 2D 방치형 게임을 제작했습니다. 자동 전투·보스전, 재화·강화·캐릭터 해금, 오프라인 보상, 저장·백업 복구, UGUI, 오브젝트 풀링 및 AdMob 연동을 다뤘습니다. Android 빌드와 Google Play Console 등록 절차까지 진행했으며, 테스터 모집 단계에서 중단해 정식 출시에는 이르지 않았습니다.

이번 프로젝트는 그 경험을 바탕으로 다음 영역에 집중합니다.

- **월드 공간의 전투:** UI 이미지와 타이머 중심 전투에서 확장해, 캐릭터가 적을 탐색·추적하고 거리와 범위에 따라 공격하도록 구현합니다.
- **에디터에서 조정하는 연출:** Animator 전이, Animation Event, Particle System을 직접 구성하고 타격 시점과 시각적 피드백을 맞춥니다.
- **측정에 근거한 최적화:** 풀링·Atlas·UI 갱신 구조의 효과를 Frame Debugger와 실기기 프로파일링으로 확인합니다.
- **실패 상황의 검증:** 저장 중 종료, 풀 재사용, 앱 복귀, SDK 초기화·네트워크 실패를 재현하고 대응 결과를 기록합니다.

‘슬레이어 키우기’의 자동 전투·방치 성장·스킬 선택과 클라이언트 개발 직무를 참고했습니다. 전투 규칙과 수치는 본 프로젝트 범위에 맞게 설계합니다.

## 플레이 방식

**자동 사냥 → 골드 획득 → 능력치 강화·스킬 선택 → 보스 도전 → 다음 단계**

- 캐릭터의 이동과 기본 공격은 자동으로 진행됩니다.
- 플레이어는 하단 UI에서 공격력·최대 체력을 강화하고, 단일 공격/범위 공격 스킬 중 하나를 장착합니다.
- 보스는 제한 시간 안에 처치해야 하며, 실패하면 일반 사냥으로 돌아가 성장한 뒤 재도전합니다.
- 재접속 시 마지막 저장 상태를 불러오고, 최대 2시간의 오프라인 보상을 정산합니다.
- 화면 상단에는 전투와 주요 상태를, 하단에는 강화·스킬 조작부를 배치합니다.

콘텐츠는 **배경 1개, 캐릭터·일반 적 각 1종, 기존 적 에셋을 활용한 보스 1종, 수치로 구분한 10단계**로 제한합니다. 기존 그림과 애니메이션 프레임을 활용하고, 씬·프리팹·Animator·파티클·UI 설정은 직접 구성합니다.

2주 범위에는 뽑기, 장비 합성, 동료, 결제·광고, 계정·랭킹, 서버 전투, iOS 및 스토어 정식 출시를 포함하지 않습니다. 일정이 부족하면 5단계·스킬 1종으로 줄이고 연출·실기기 검증 시간을 확보합니다.

## 개발 환경 및 설계 방향

현재 에디터와 설치 패키지 버전은 프로젝트 설정 파일 기준입니다. 도입 예정 기술과 게임 내 설정은 구현 과정에서 검증합니다.

| 구분 | 현재 환경 / 예정 구성 |
| --- | --- |
| 엔진·언어 | Unity **6000.6.4f1** · C# |
| 렌더링 | URP **17.6.0** 설치 · 2D Renderer, Pixel Perfect Camera, Sprite Atlas 활용 예정 |
| 인터페이스 | UGUI **2.6.0** 설치 · TextMeshPro, Screen Space Overlay Canvas 활용 예정 |
| 연출 | Animator · Animation Event · Particle System |
| 데이터·저장 | ScriptableObject · 버전 필드를 포함한 JSON 저장 |
| 외부 SDK | Firebase Remote Config — 프로젝트 초기 단계에 호환 버전 확인 |
| 분석 도구 | Unity Profiler · Frame Debugger · Memory Profiler · Android 로그 |

전투 판단·성장 계산·저장·화면 표시의 책임을 분리합니다. 기본 타깃 탐색은 활성 적 목록을 일정 주기로 순회하는 방식으로 시작하고, 성능 측정 결과에 따라 조정합니다. 오프라인 보상은 로컬 시간 기반의 제한된 구현이며, 서버 기반 시간 검증은 포함하지 않습니다.

Firebase는 원격 설정과 실패 대응을 실습하기 위한 선택입니다. 기존 AdMob 경험과 구분해 적용 이유와 연동 과정을 기록하며, 원작 게임의 사용 SDK를 의미하지 않습니다.

## 검증 기준

- **전투·상태:** 공격 모션과 피해 시점을 맞추고, 타깃 사망·공격 중단·보스 재도전·풀 재사용 시 중복 타격과 상태 잔류가 없는지 확인합니다.
- **저장·보상:** 자원 부족, 최대 강화 레벨, 시간 역행, 보상 상한, 중복 정산, 저장 버전 변환을 검증합니다. 계산 로직에는 작은 자동 테스트를 작성합니다.
- **모바일 성능:** 동일 기기·해상도·목표 FPS에서 적 20마리와 고정된 스킬 사용 주기로 워밍업 후 60초씩 3회 측정합니다. 프레임 시간 중앙값·95백분위수, CPU/GPU 시간(측정 가능한 경우), GC Alloc, 드로우콜 및 메모리를 기록합니다.
- **메모리:** 10분 플레이와 보스 입퇴장·탭 전환 20회 전후를 같은 화면·정리 상태에서 비교합니다. 풀 확장에 따른 초기 증가와 계속 누적되는 객체를 구분합니다.
- **운영 상황:** 네트워크 실패에도 게임을 시작할 수 있는지, 원격 설정을 정상 값으로 되돌릴 수 있는지, 같은 앱 ID·서명의 v0.2 설치 후 저장이 유지되는지 확인합니다.

일반 플레이의 목표는 **60fps**이며 아직 검증되지 않았습니다. 기기·OS·빌드 설정·발열 조건을 기록하고, Frame Debugger와 메모리 캡처는 프레임 시간 측정과 분리합니다. 최적화는 한 항목씩 비교하고 효과가 없었던 변경도 기록합니다.

## AI 활용 및 개발 기록

AI는 설계 후보 비교, 구현 보조, 테스트 사례 도출 및 오류 분석에 활용합니다. 에디터 설정과 구현 결과는 직접 확인하고, 주요 결정은 다음 형식으로 남깁니다.

**문제·목표 → AI 제안 → 채택/기각 이유 → 직접 확인한 결과**

씬·프리팹·Animator·렌더링 설정 변경도 기능 단위로 커밋하고, 변경 이유와 확인 방법을 기록합니다. 개인 테스트 피드백은 이슈로 정리해 개선 전후를 비교합니다. 테스트 빌드 운영 경험과 상용 라이브 서비스·다직군 협업 경력은 구분합니다.

## 실행 및 빌드

1. 저장소를 내려받고 Unity Hub에서 저장소 내부의 `rift_guardian_idle/` 폴더를 추가합니다.
2. Unity **6000.6.4f1**로 열고 패키지 복원과 초기 임포트를 기다립니다.
3. 프로젝트 내부의 `Assets/Scenes/SampleScene.unity`를 엽니다. 현재는 기본 씬이며 플레이할 게임 기능은 아직 없습니다.

Android 빌드·실기기 실행과 Firebase 연동은 아직 검증하지 않았습니다. 첫 빌드 검증 후 필요한 Android 모듈, 빌드 프로필, Firebase 설정 및 설치 절차를 추가합니다.
